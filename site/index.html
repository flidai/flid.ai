01 · LeapView · Open source

Define a metric once. Use it everywhere.

Open-source business intelligence on your own infrastructure. See LeapView

  1. 01

    Write it once, in code

    Revenue is a few lines of YAML in a semantic model, kept in Git and reviewed like any other change.

  2. 02

    Put it on a dashboard

    KPI cards, charts and tables ask for the metric by name. LeapView plans each query, applies access rules and runs it in DuckDB.

  3. 03

    The same number everywhere

    Dashboards, the API and AI tools all read the one definition of revenue, so the totals agree.

  4. 04

    Ask in plain language

    Built-in chat answers from the same models with each person’s own access. Other AI assistants connect through an MCP endpoint.

02 · Alloy Catalog · Pilots open

Every part, every source, one catalog.

Engineering master data from your CAD files and ERP, with a built-in AI agent. Shown on a made-up demo catalog. See Alloy Catalog

  1. 01

    Find it by what it is

    Search by material, class or where a part is used, not by file name. Here, one stainless steel grade finds 41 items.

  2. 02

    Every part on one page

    Bill of materials, where-used, drawings, revision and ERP status for each part number, with the source of every value.

  3. 03

    See where the data disagrees

    A data quality score and the conflicts between CAD and ERP, listed so they get fixed instead of hidden.

  4. 04

    Ask, and check the sources

    The built-in AI agent answers questions about parts and cites every model and drawing it names.

Situation
A data team whose dashboards each define revenue and margin slightly differently, with access rules kept by hand per report.
What Flid does
Moves connections, models, metrics and dashboards into YAML in Git with LeapView, validated before publishing, with row filters and column masks applied in one place. LeapView is an alpha, so this starts as an evaluation.
What changes
One definition per metric, used by dashboards, headless queries and AI tools. Changes go through review like code.
Runs on
LeapView, DuckDB and PostgreSQL on the team’s own infrastructure.
