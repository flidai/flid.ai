Features

Your business intelligence should belong to your business.

Definitions in your Git repository, data on your infrastructure, access rules in one place.

  • Analytics as code

    Connections, transformations, semantic models, refresh pipelines and dashboards are YAML files in Git, reviewed like any other change. LeapView validates the whole project before it publishes, and you can preview a private candidate first.

  • One definition per metric

    Dimensions, relationships and business calculations are defined once in a semantic model. Every dashboard, API query and AI tool uses the same definition.

  • Dashboards and tables

    26 visual types: charts, maps, KPI cards, tables, matrices and pivots, with filters, cross-highlighting and conditional formatting. A browser builder drafts and previews dashboards and exports YAML.

  • Connect the data you have

    PostgreSQL, MySQL, SQLite and DuckLake; files in S3, R2, Google Cloud Storage, Azure Blob or over HTTP, as CSV, Parquet, JSON, Excel, Delta or Iceberg. Uploaded data is versioned and goes live with a deployment.

  • Decide who sees what

    Roles, resource grants, row filters and column masks apply in the query layer, to dashboards, APIs and AI tools alike. Single sign-on with OIDC, including Microsoft Entra ID; users and groups kept in sync with SCIM; an audit trail of access changes and queries.

  • AI with the same rules

    Built-in chat on an OpenAI-compatible provider your administrator chooses. Claude and other AI assistants connect through an OAuth-protected MCP endpoint, with each person’s own access.

  • Share and embed

    Publish a dashboard at a public link or embed it on your own site, still governed by data policies. Share explorations by link, and download results as CSV or Parquet.

  • Headless and open

    Query dashboards and semantic models through the API and the command line. Use dbt’s tested tables as input, and import or export semantic models with Apache Ossie.

  • Run it yourself

    Go serves the application, DuckDB runs the queries, DuckLake keeps the analytical snapshots and PostgreSQL stores the rest. A public Docker image, a Compose package, and a command-line tool for Linux and macOS.

How it works

From a connection to a dashboard.

Each step is a YAML resource in the same project, checked together before anything is published.

  1. Connect

    A connection points at a database, a bucket or uploaded files; a source names the tables and files you use.

  2. Model

    Models clean and join the data. A semantic model adds the business meaning: datasets, dimensions, metrics and relationships.

  3. Present

    Dashboards, the API and AI tools ask for metrics by name. LeapView plans each query, applies access rules and runs it in DuckDB.

  4. Publish

    Validate the project, preview the candidate, then publish that exact revision. Pipelines refresh the data without interrupting readers.

Example

A metric in code.

Revenue, defined once in a semantic model. A KPI card shows the total, a trend groups it by month and a chart by category; all three refer to it by name.
